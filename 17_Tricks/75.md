LeetCode 第75题**“颜色分类”（Sort Colors）**要求在一个只包含 0、1、2 的数组中进行原地排序，使得相同颜色的元素相邻，并且按 0、1、2 的顺序排列。

这个问题其实就是著名的计算机科学家 Dijkstra（迪杰斯特拉）提出的**“荷兰国旗问题”（Dutch National Flag Problem）**。因为荷兰国旗恰好由红、白、蓝三色组成，自上而下排列，对应了这里的 0、1、2。

解决这个问题的最优解法就是**双指针法（三指针法）**，只需遍历数组一次，时间复杂度 $O(N)$，空间复杂度 $O(1)$。

下面为你详细讲解这个算法的原理和实现过程：

### 1. 核心思想
我们将数组分成三个区域：
*   **左侧区域**：全部放 `0`
*   **中间区域**：全部放 `1`
*   **右侧区域**：全部放 `2`

为了维护这三个区域，我们需要三个指针：
1.  `p0`（左指针）：指向**下一个应该存放 0** 的位置。它左边的所有元素都是 0。
2.  `p2`（右指针）：指向**下一个应该存放 2** 的位置。它右边的所有元素都是 2。
3.  `curr`（当前指针）：用于遍历数组，逐个审查元素。

### 2. 状态转移逻辑
我们让 `curr` 从头开始遍历数组（初始 `curr = 0`），循环的条件是 `curr <= p2`（因为 `p2` 右边的已经是 2 了，不需要再检查，但 `p2` 当前指向的位置还没检查过）。

对于当前正在检查的元素 `nums[curr]`，会有三种情况：

*   **情况 A：`nums[curr] == 0`**
    说明这个数字属于最左边。我们将 `nums[curr]` 与 `nums[p0]` 互换。
    换完之后，左边多了一个 0，所以 `p0` 向右移动一步（`p0++`）。同时，因为从 `p0` 换过来的数字一定是被 `curr` 扫描过的 `1`（或者就是 `curr` 自己），所以当前位置没问题了，`curr` 也向右移动一步（`curr++`）。
*   **情况 B：`nums[curr] == 1`**
    说明这个数字刚好属于中间区域，不用动它。
    直接 `curr` 向右移动一步（`curr++`）。
*   **情况 C：`nums[curr] == 2`**
    说明这个数字属于最右边。我们将 `nums[curr]` 与 `nums[p2]` 互换。
    换完之后，右边多了一个 2，所以 `p2` 向左移动一步（`p2--`）。
    **【注意！这是最容易错的地方】** 此时 `curr` **千万不能动**。因为从末尾 `p2` 换过来的新数字我们还没有检查过，它可能是 0、1 或者 2。我们要把它留在 `curr` 的位置，下一轮循环继续检查它。

### 3. 代码实现 (Python & Java)

**Python 实现：**
```python
class Solution:
    def sortColors(self, nums: List[int]) -> None:
        """
        Do not return anything, modify nums in-place instead.
        """
        p0 = 0
        curr = 0
        p2 = len(nums) - 1
        
        while curr <= p2:
            if nums[curr] == 0:
                # 遇到 0：和 p0 交换，p0 和 curr 都前进一步
                nums[curr], nums[p0] = nums[p0], nums[curr]
                p0 += 1
                curr += 1
            elif nums[curr] == 1:
                # 遇到 1：直接跳过
                curr += 1
            else:
                # 遇到 2：和 p2 交换，p2 后退一步，curr 停在原地继续审查交换过来的新元素
                nums[curr], nums[p2] = nums[p2], nums[curr]
                p2 -= 1
```

**Java 实现：**
```java
class Solution {
    public void sortColors(int[] nums) {
        int p0 = 0;
        int curr = 0;
        int p2 = nums.length - 1;

        while (curr <= p2) {
            if (nums[curr] == 0) {
                swap(nums, curr, p0);
                p0++;
                curr++;
            } else if (nums[curr] == 1) {
                curr++;
            } else { // nums[curr] == 2
                swap(nums, curr, p2);
                p2--;
                // 注意这里没有 curr++
            }
        }
    }

    private void swap(int[] nums, int i, int j) {
        int temp = nums[i];
        nums[i] = nums[j];
        nums[j] = temp;
    }
}
```

### 4. 动画般的手工模拟（Dry Run）
我们用一个具体的例子 `[2, 0, 2, 1, 1, 0]` 来过一遍：
初始：`nums =[2, 0, 2, 1, 1, 0]`，`p0 = 0`, `curr = 0`, `p2 = 5`

1.  `curr=0`, `nums[0]=2`：触发**情况C**。与 `p2(5)` 交换。
    数组变 `[0, 0, 2, 1, 1, 2]`, `p2=4`，`curr` 不变(`curr=0`)。
2.  `curr=0`, `nums[0]=0`：触发**情况A**。与 `p0(0)` 交换（自己换自己）。
    数组不变，`p0=1`, `curr=1`。
3.  `curr=1`, `nums[1]=0`：触发**情况A**。与 `p0(1)` 交换。
    数组不变，`p0=2`, `curr=2`。
4.  `curr=2`, `nums[2]=2`：触发**情况C**。与 `p2(4)` 交换。
    数组变 `[0, 0, 1, 1, 2, 2]`, `p2=3`，`curr` 不变(`curr=2`)。
5.  `curr=2`, `nums[2]=1`：触发**情况B**。无需交换。
    数组不变，`curr=3`。
6.  `curr=3`, `nums[3]=1`：触发**情况B**。无需交换。
    数组不变，`curr=4`。
7.  此时 `curr(4) > p2(3)`，循环结束。

最终数组变成 `[0, 0, 1, 1, 2, 2]`，完全排序成功。

### 5. 复杂度分析
*   **时间复杂度：$O(N)$**。`curr` 指针和 `p2` 指针相向而行，每进行一次操作，要么 `curr` 加 1，要么 `p2` 减 1。它们最多相遇一次，因此总体只遍历了数组一遍。
*   **空间复杂度：$O(1)$**。除了三个指针变量，不需要使用额外的内存空间，满足原地排序（in-place）的要求。

要彻底弄懂这个问题，我们需要观察 `p0` 和 `curr` 这两个指针的**相对运动速度**，以及它们之间夹着的是什么元素。

你可以记住一个核心结论：**在整个遍历过程中，`curr` 永远大于或等于 `p0`。而在 `p0` 到 `curr` 之间（即 `[p0, curr)` 这个区间），如果存在元素，那它们绝对全部都是 `1`。**

下面为您详细拆解原因：

### 1. 为什么 `curr` 总是跑在 `p0` 前面（或者重合）？
*   当 `curr` 遇到 `0` 时：`curr` 和 `p0` **同时**前进一步。
*   当 `curr` 遇到 `1` 时：`curr` 前进一步，但 `p0` **不动**。
*   当 `curr` 遇到 `2` 时：`curr` 和 `p0` 都**不动**（与后方交换）。

发现了吗？`p0` 只有在遇到 0 的时候才走，而 `curr` 遇到 0 和 1 都会走。所以 `curr` 的前进速度 $\ge$ `p0` 的前进速度。这就导致了两种情况：

#### 情况 A：`curr == p0`（两个指针重合）
如果 `curr` 一直没有遇到过 `1`，那么 `p0` 和 `curr` 会一直紧挨着重合。
这时候如果 `nums[curr] == 0`，它和 `p0` 交换，其实就是**自己和自己交换**。交换过来的数字还是刚才扫描的 `0`（处理完毕了），所以 `curr` 安心向前走一步即可。

#### 情况 B：`curr > p0`（`curr` 跑到了 `p0` 前面）
`curr` 凭什么能跑到 `p0` 前面？**唯一的可能就是 `curr` 之前遇到过 `1`。**
因为遇到 `1` 时，`curr` 会跨过去（`curr++`），但 `p0` 会停留在原地，这就拉开了差距。
这就意味着，**`p0` 指向的必定是 `curr` 曾经跨过去的第一块“砖”，也就是 `1`**。

### 2. p0 指向的有没有可能是 2？
**绝对不可能。**
因为如果 `curr` 在此之前扫描到了 `2`，它当场就会触发“情况C”，把这个 `2` 丢到数组最后面（和 `p2` 交换）去了，并且 `curr` 会停在原地，直到交换过来一个不是 `2` 的数字才敢继续往右走。
所以，能够被 `curr` 放过、留在 `p0` 到 `curr` 之间的数字，只可能是 `1`。

---

### 💡 举个极简的例子来验证

假设数组是 `[1, 0, 2]`：
*   **初始：** `p0 = 0`, `curr = 0`。
*   **第 1 步：** `curr=0` 遇到 `1`。`curr` 走一步（`curr=1`），`p0` 不动（`p0=0`）。
    *此时差距拉开了！`p0` 留在了索引 0，指向的是 `1`。*
*   **第 2 步：** `curr=1` 遇到 `0`。触发“和 `p0` 交换”。
    把 `nums[curr]`（也就是0）和 `nums[p0]`（也就是1）互换。
    换完后数组变成了 `[0, 1, 2]`。

你看，此时从 `p0` 换到 `curr` 位置上的数字，**正是刚才第一步里 `curr` 扫描过并且跨过去的那个 `1`**！
既然我们百分之百确定换过来的是个乖乖听话的 `1`，那 `curr` 就可以放心地直接 `++`，继续去检查下一个数字了。

**总结一下：**
遇到 `0` 交换时，换过来的要么是自己（`curr == p0`），要么是被自己之前放过的 `1`（`curr > p0`）。两者都是安全且合法的状态，不需要重新扫描，所以 `curr` 可以放心 `++`。而遇到 `2` 时，从末尾换过来的盲盒数字毫无保证，所以 `curr` 必须待在原地审查它。
