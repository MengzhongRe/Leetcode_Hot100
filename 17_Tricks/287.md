## 为什么快慢指针相遇能够推导出链表入环点？

用快慢指针寻找链表入环点的方法（即**Floyd 判圈算法**，常用于解决 LeetCode 142 题）非常巧妙。要从数学上严谨地证明它的正确性，我们可以通过设立未知数、列方程、化简和物理解释这四个步骤来完成。

以下是详细的数学证明过程：

### 一、 建立数学模型与变量定义

假设链表存在环。我们把链表分为两部分：**直线部分**和**环形部分**。
我们定义以下几个距离变量（距离单位为“节点数”或“步数”）：

*   **$a$**：从链表头节点（Head）到入环点（Entry）的距离。
*   **$b$**：从入环点（Entry）顺时针走到快慢指针**第一次相遇点**（Meeting Point）的距离。
*   **$c$**：从相遇点（Meeting Point）继续顺时针走到入环点（Entry）的剩余距离。

基于以上定义，可以得出：
*   环的周长 $L = b + c$。

---

### 二、 分析相遇时的路程关系

在第一阶段，慢指针（每次走1步）和快指针（每次走2步）从头节点同时出发，直到它们在环内相遇。

**1. 慢指针行驶的距离 ($S_{slow}$)**：
慢指针走过直线部分 $a$，进入环后走了 $b$ 步被快指针追上。
*(引理：为什么慢指针在环内走不到一圈就会被追上？因为当慢指针刚入环时，快指针已经在环内某处。二者的相对速度是每次 1 步，快指针最多只需要走 $L-1$ 步就能追上慢指针，而慢指针走一圈需要 $L$ 步。因此慢指针在第一圈内必定被追上)*。
所以，慢指针的总路程：
$$S_{slow} = a + b$$

**2. 快指针行驶的距离 ($S_{fast}$)**：
快指针走过直线部分 $a$，然后在环内转了 $n$ 圈（$n \ge 1$），最后又走了 $b$ 步到达相遇点。
所以，快指针的总路程：
$$S_{fast} = a + n(b + c) + b$$

**3. 建立等式**：
因为快指针的速度是慢指针的 **2 倍**，且它们运动的时间相同，所以快指针走过的总距离等于慢指针的 2 倍：
$$S_{fast} = 2 \times S_{slow}$$

将前面的式子代入：
$$a + n(b + c) + b = 2(a + b)$$

---

### 三、 代数推导与方程化简

现在，我们需要解这个方程，目标是找出 $a$（因为我们的最终目的是要找到入环点，即走完距离 $a$ 的终点）。

展开等式右边：
$$a + n(b + c) + b = 2a + 2b$$

将包含 $a$ 的项移到方程一侧，其他项移到另一侧：
$$2a - a = n(b + c) + b - 2b$$
$$a = n(b + c) - b$$

为了赋予这个等式几何意义，我们将右侧的 $n(b+c)$ 拆解出一个 $(b+c)$：
$$a = (n - 1)(b + c) + (b + c) - b$$

化简最后一项 $(b + c) - b$，得到最终的核心等式：
$$a = (n - 1)(b + c) + c$$

由于 $b + c = L$ (环的周长)，等式可以写为：
**$$a = (n - 1)L + c$$**

---

### 四、 核心等式的物理/几何解释（证明第二阶段的正确性）

我们得到了极其重要的结论：**$a = (n - 1)L + c$**。
这个等式完美地解释了算法的第二阶段为什么要那样做。

**算法第二阶段的操作是**：
1. 将慢指针（或快指针）重新指向链表头节点（Head）。
2. 另一个指针保持在相遇点（Meeting Point）。
3. 两个指针都以**每次 1 步**的速度同时前进，直到它们相遇。

**为什么它们一定会在入环点相遇？**
让我们结合等式 $a = c + (n - 1)L$ 来看这两个指针的运动：

*   **指针 1（从头节点出发）**：它以速度 1 前进，走过距离 **$a$** 时，刚好到达**入环点**。
*   **指针 2（从相遇点出发）**：它以速度 1 前进，走过同样的距离 **$a$** 时，会停在哪里呢？
    根据等式 $a = c + (n - 1)L$，指针 2 走过距离 $a$ 等价于：
    它先走了距离 **$c$**（刚好从相遇点走回到了**入环点**）；
    然后它又继续走了 **$(n - 1)L$** 的距离，也就是在环里绕了 $n - 1$ 整圈。
    绕完 $n-1$ 整圈后，它依然停在**入环点**。

### 五、 结论

综上所述，当从头节点出发的指针走了 $a$ 步到达入环点时，从相遇点出发的指针恰好也走了 $a$ 步（先走 $c$ 步到达入环点，然后转了 $n-1$ 圈），同样到达了入环点。

**因此，这两个指针第一次相遇的地方，必定是且恰好是链表的入环节点。** 证毕。

## 如何用快慢指针判入环点解决287寻找重复数问题？

### 一、 核心洞察：如何将“数组”变成“链表”？

题目给出的条件非常特殊：给定一个包含 $n + 1$ 个整数的数组 `nums`，其数字都在 $[1, n]$ 范围内。

我们可以把数组中的**索引（下标）**和**对应的值**看作是链表中的**节点**和**next 指针**。
映射关系是：**`当前节点 -> 下一个节点`  等价于  `当前索引 -> 数组在当前索引的值 (nums[index])`**。

#### 为什么一定有环？
因为数组有 $n + 1$ 个元素，但值域只有 $[1, n]$。这意味着按照 `index -> nums[index]` 不断跳跃，你的下一个索引永远在 $[1, n]$ 范围内，绝对不会越界（因为没有任何值会超出边界）。既然步数无限但节点有限，**必然会陷入死循环（环）**。

#### 为什么“重复的数字”就是“入环点”？
在这个映射下，**如果有多个索引指向了同一个值，就意味着有多个节点指向了同一个节点。**
在一条单向链表中，如果有一个节点被两个或多个节点指向（入度 $\ge 2$），那么这个节点必定是**环的起点（入环点）**！

**举个具体例子：**
假设数组 `nums = [1, 3, 4, 2, 2]`，索引是 `0, 1, 2, 3, 4`。
我们从索引 `0` 出发，进行跳跃 `next = nums[curr]`：
* 索引 `0` 的值是 `1` ➡️ 跳到索引 `1`
* 索引 `1` 的值是 `3` ➡️ 跳到索引 `3`
* 索引 `3` 的值是 `2` ➡️ 跳到索引 `2`
* 索引 `2` 的值是 `4` ➡️ 跳到索引 `4`
* 索引 `4` 的值是 `2` ➡️ 跳到索引 `2` (进入了环！)

链表路径为：`0 -> 1 -> 3 -> 2 -> 4 -> 2 -> 4 -> 2...`
显然，环的入口是节点 `2`，而 `2` 正是数组中的重复元素！
（此外，注意**起点必须是 0**。因为数组的值在 $[1, n]$，没有任何元素的值为 0，所以索引 0 绝对不会在环内，它就像链表的头节点。）

---

### 二、 算法步骤（套用公式）

既然问题转化为了“寻找链表的入环点”，我们直接套用前面证明过的两阶段算法：

**阶段 1：判断相遇点**
1. 初始化慢指针 `slow = 0` 和快指针 `fast = 0`。
2. 慢指针走一步：`slow = nums[slow]`。
3. 快指针走两步：`fast = nums[nums[fast]]`。
4. 重复直到 `slow == fast`，找到相遇点。

**阶段 2：寻找入环点（即重复数字）**
1. 相遇后，将其中一个指针（比如慢指针 `slow`）**重新放回起点 `0`**。
2. 另一个指针（`fast`）保持在相遇点。
3. 两个指针这次**都每次走一步**：`slow = nums[slow]`，`fast = nums[fast]`。
4. 它们根据我们在上一个回答中推导的等式 $a = (n-1)L + c$，必定会在**入环点**相遇。
5. 相遇时的值，就是我们要找的重复数字！

---

### 三、 代码实现

这套逻辑写成代码极其简洁，而且完美符合 $O(n)$ 时间复杂度和 $O(1)$ 空间复杂度的要求，且没有修改原数组。

#### Python 3
```python
class Solution:
    def findDuplicate(self, nums: List[int]) -> int:
        # 第一阶段：快慢指针寻找相遇点
        slow = 0
        fast = 0
        while True:
            slow = nums[slow]           # 慢指针走一步
            fast = nums[nums[fast]]     # 快指针走两步
            if slow == fast:            # 必定会相遇，因为有环
                break
        
        # 第二阶段：寻找入环点（重复数字）
        slow = 0                        # 慢指针回到起点（对应距离 a）
        while slow != fast:
            slow = nums[slow]           # 每次都走一步
            fast = nums[fast]
            
        return slow                     # 相遇点即为重复元素
```
### 总结
这种解法之所以让人拍案叫绝，就是因为它将看似毫无关联的“数组找重”问题，通过**值即指针**的映射，抽象成了拓扑图/链表找环的问题。一旦建立了这个思维映射，背后的数学原理（之前严格证明过的路程推导 $a = (n-1)L + c$）就会自然而然地推导出现成的代码，优雅且高效。

## 为什么入环点一定就是重复数字？

这是一个非常深刻且直击本质的问题。要严谨地证明“**入环点必定是重复数字**”，我们需要从**图论**（Graph Theory）中的“节点入度（In-degree）”角度来进行逻辑推演。

我们可以分四个步骤来把这个逻辑锁死：

### 1. 明确“边”的定义
我们将数组的映射关系转化为有向图：
*   **节点（Node）**：数组的下标（索引），范围是 `0` 到 `n`。
*   **有向边（Edge）**：从下标 `i` 指向它所对应的值 `nums[i]`，即 `i -> nums[i]`。
*   因为数组每个位置只有一个值，所以**每个节点的“出度”（向外指的箭头）必定且仅为 1**。

### 2. 起点 `0` 为什么绝对不在环内？
题目有一个关键条件：数组大小为 `n + 1`，但里面的数字范围都是 `[1, n]`。
这意味着什么？
*   **没有任何一个 `nums[i]` 的值会等于 `0`。**
*   在图论中，这就意味着**节点 `0` 的“入度”为 0**（没有任何箭头指向 `0`）。
*   既然没有箭头指向 `0`，`0` 永远无法被二次访问，它**绝对不可能在环（Cycle）里面**。
*   所以，节点 `0` 只能作为一条单向路径的起始点（链表头），最终通向某个环。

### 3. “入环点”在图论中意味着什么？
我们想象一下，从起点 `0` 出发，沿着箭头一路走，最终会进入一个死循环（环）。
*   当你**第一次**踏入这个环时，你踩到的那个节点，就是**入环点**。
*   既然它是入环点，说明它是连接“直线部分”和“环形部分”的枢纽。
*   这就意味着，**必然有至少两个箭头指向它**：
    1.  一个是来自环外的直线部分（把你带入环的那一步）。
    2.  一个是来自环内的绕圈部分（在环里转了一圈后回到这里的首尾相接的那一步）。
*   所以，**入环点的“入度”（指向它的箭头数量）必定 $\ge 2$**。

### 4. 翻译回数组语言：入度 $\ge 2$ 是什么意思？
在我们的映射规则 `i -> nums[i]` 中：
*   如果有两个不同的箭头指向了节点 `V`，假设是从节点 `x` 和节点 `y` 指过来的。
*   这说明：`nums[x] = V`，并且 `nums[y] = V`。
*   在数组中，**两个不同的索引 `x` 和 `y`，存储了相同的值 `V`**。
*   这不就是**重复数字**的严谨定义吗！

---

### 结合一个具体例子来看：

假设 `nums = [1, 3, 4, 2, 2]` （索引是 0 到 4）。
画出有向边 `i -> nums[i]`：
*   `0 -> 1` （索引 0 的值是 1）
*   `1 -> 3` （索引 1 的值是 3）
*   `3 -> 2` （索引 3 的值是 2）
*   `2 -> 4` （索引 2 的值是 4）
*   `4 -> 2` （索引 4 的值是 2）

你可以看到：
1.  节点 `0` 没有被任何人指向，它是绝对的起点。
2.  路径是：`0 -> 1 -> 3 -> 2 -> 4 -> 2 -> 4 -> 2 ...`
3.  在这个图里，**节点 `2` 被节点 `3` 指向了（`nums[3]=2`），同时也被节点 `4` 指向了（`nums[4]=2`）**。
4.  所以节点 `2` 的入度为 2，它是入环点。
5.  同时，`nums[3]` 和 `nums[4]` 的值都是 2，所以 2 就是那个重复数字。

### 结论
**因为每个索引只有一个值（出度恒为1），所以形成环的唯一方式，必定是存在某个节点被多个其他节点指向（入度 $\ge 2$）。而“多个节点指向同一个节点”，在数组映射中完全等价于“多个索引对应同一个值”，即这个节点的值就是重复数字。**
