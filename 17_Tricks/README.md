## 力扣hot100 技巧题目解析

### 🧠 为什么要有“技巧”这个单独的单元？

以前你刷的题，比如动态规划、二叉树，都是有**通用模板和框架**的。只要你掌握了套路，哪怕遇到新题也能顺藤摸瓜推导出来。

但“技巧”单元的题目**没有通用框架，它们本质上是“脑筋急转弯”或者“历史上某位计算机科学家的专属发明”**。
这些题目的共同特点是：
1. **常规解法极其简单**：你用哈希表、排序或者暴力破解，几分钟就能写出来，但是空间复杂度是 $O(N)$，或者时间复杂度是 $O(N \log N)$。
2. **最优解法极度反直觉**：题目往往会附加一个极其变态的限制条件（比如：**只能使用 $O(1)$ 的额外空间，且时间复杂度必须是 $O(N)$**）。
3. **“会者不难，难者不会”**：如果你不知道那个特定的“奇技淫巧”，考场上给你 3 个小时你也想不出来；但如果你背过那个技巧，代码往往只有不到 10 行。

力扣把它们单列出来，就是在告诉你：**不要在这些题上死磕推导，直接去学前人的智慧结晶！**

### 🔮 这 5 道题的“底牌”都是什么？（剧透预警）

这 5 道题每一道都对应着计算机科学史上的一个经典小算法或数学特性。我为你一句话总结它们的“破局点”：

#### 1. 只出现一次的数字 (Single Number)
*   **常规想法**：用 Hash 表记录每个数字出现的次数（空间 $O(N)$）。
*   **满分技巧：位运算（异或 XOR）**。
*   **底牌揭秘**：利用异或的数学性质：`a ^ a = 0` 且 `a ^ 0 = a`。把数组里所有的数字全都异或一遍，成对的数字全变成了 0，最后剩下的那个数字就是落单的！代码只有 3 行，空间 $O(1)$。

#### 2. 多数元素 (Majority Element)
*   **常规想法**：用 Hash 表统计频率，或者排序后取中间的数。
*   **满分技巧：摩尔投票法 (Boyer-Moore Voting Algorithm)**。
*   **底牌揭秘**：把它想象成“诸侯争霸”。不同国家的士兵遇到就**一换一同归于尽**，同一个国家的士兵遇到就汇合。因为“多数元素”的数量超过了总数的一半，哪怕它和所有其他元素一换一，最后活下来的也必定是它！空间 $O(1)$。

#### 3. 颜色分类 (Sort Colors)
*   **常规想法**：直接调用 `sort()`，或者扫描两遍（先数个数，再重写数组）。
*   **满分技巧：荷兰国旗问题 (Dutch National Flag)**。这是大名鼎鼎的 Dijkstra（对，就是发明最短路径那个大佬）提出来的。
*   **底牌揭秘**：只遍历**一次**！用三个指针（left, curr, right），遇到 0 扔到最左边，遇到 2 扔到最右边，遇到 1 跳过。一遍扫完，自然就排好序了。空间 $O(1)$。

#### 4. 下一个排列 (Next Permutation)
*   **常规想法**：暴力找出所有排列，排序后找下一个（直接超时）。
*   **满分技巧：观察数学规律**。
*   **底牌揭秘**：纯粹的逻辑推导题。如何让一个数字稍微变大一点点？从后往前找第一个“下降”的数字，然后把它和后面比它稍微大一点的数字交换，最后把后面的尾巴反转成升序。没有任何算法，全是观察力。

#### 5. 寻找重复数 (Find the Duplicate Number)
*   **常规想法**：用 Set 判重（违反空间限制），或者排序（违反不能修改原数组的限制）。
*   **满分技巧：快慢指针（把数组当成链表找环）**。
*   **底牌揭秘**：极其脑洞大开！把数组里的“值”当成指向下一个“下标”的指针。因为有重复的数字，所以多个下标会指向同一个值，这就必然会形成一个**“带环链表”**！找重复的数字，其实就是**找链表环的入口**！直接套用经典的“龟兔赛跑”快慢指针算法。时间 $O(N)$，空间 $O(1)$。

### 📝 刷这个单元的正确姿势

1. **别跟自己死磕**：如果在最优解（空间 $O(1)$）上卡了 10 分钟没思路，**立刻去看题解**！不要有挫败感，因为没人能在考场上临时发明“摩尔投票法”。
2. **当成背诵题**：这 5 道题是面试中非常喜欢考的**“鉴渣题”**。面试官考你这些，不是为了看你的推理能力，而是单纯考你**“有没有认真准备过面试”**。你不仅要敲出代码，还要能向面试官讲出背后的名字（比如“摩尔投票法”、“快慢指针判环”），面试官会觉得你基础极其扎实。
