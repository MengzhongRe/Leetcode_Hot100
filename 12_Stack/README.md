# 🚀 算法精进笔记：栈 (Stack) 的进阶与升维打击

> **💡 核心定义**：栈不仅仅是一个“后进先出 (LIFO)”的数据结构，它在计算机科学中的本质是一台**“时光机”**。
> 当我们需要**“保存现场 $\rightarrow$ 处理分支 $\rightarrow$ 恢复现场”**，或者需要**“状态回退”**时，栈永远是唯一的完美解。

---

## 🟢 1. 力扣 20. 有效的括号 (栈的对称与消除)

### 📝 解题思路
处理嵌套或并列的成对符号，核心规则是**“最近匹配原则”**。
遇到左括号就压入栈中（等待匹配）；遇到右括号，就检查栈顶（最近的一个左括号）是否与其成对。一旦匹配成功就弹出，如果最后栈被完全清空，说明所有括号完美闭合。

### 🚀 优化过程 (我的极客微操)
1. **极限剪枝**：`if len(s) % 2 != 0: return False`。成对出现的字符总数必定是偶数，提前拦截所有奇数长度的无效输入，在 $O(1)$ 时间内秒杀大量测试用例。
2. **巧用哈希映射**：构建 `mapping = {')':'(', ']':'[', '}':'{'}`。不但消除了丑陋的 `if-elif` 堆砌，还实现了极强的扩展性（未来增加 `<>` 匹配也只需改一行代码）。
3. **反向判断与优雅收尾**：遍历时遇到右括号直接查字典比对，最后用 Pythonic 的 `return not stack` 代替繁琐的长度判断。

### 💻 核心代码 (Python)
```python
class Solution(object):
    def isValid(self, s):
        # 1. 奇数长度极速剪枝
        if len(s) % 2 != 0:
            return False
            
        mapping = {')': '(', ']': '[', '}': '{'}
        stack = []
        
        for char in s:
            if char in mapping:
                # 遇到右括号，弹出栈顶比对；若栈空则用 '#' 占位防报错
                top_element = stack.pop() if stack else '#'
                if mapping[char] != top_element:
                    return False
            else:
                # 遇到左括号，无脑压栈
                stack.append(char)
                
        # 栈空则完美匹配，非空则有多余左括号
        return not stack
```

### ⏱ 复杂度分析
* **严格时间复杂度**：$O(N)$。遍历一次字符串，哈希表查询和栈的 `pop/append` 的摊还时间复杂度均为 $O(1)$。
* **严格空间复杂度**：$O(N + |\Sigma|)$。$N$ 为全左括号时的栈深最大开销；$|\Sigma|$ 代表哈希表中维护的字符集（Alphabet Size）映射常数空间。

## 🟡 2. 力扣 155. 最小栈 (状态绑定与时光倒流)

### 📝 解题思路
题目要求在标准栈的基础上，实现 $O(1)$ 级别获取最小值 `getMin()`。
栈的灵魂是 LIFO，当我们 `pop` 掉一个元素时，栈不仅要回退数据，还要**完美回退当时的最小值状态**。

### 🚀 优化过程 (工程常数优化 vs 理论极限)
* **我的工程优化思路**：维护一个全局 `self.min`，在 `pop` 时通过 `if poped_val == self.min` 进行剪枝。只有极小概率遇到最小值被弹出时，才使用 $O(N)$ 重新遍历。这种方法利用了底层 C 语言极其高效的 `min()` 函数，在实际工程中跑得极快。
* **终极理论最优解（元组存状态）**：为了满足面试中严格的 $O(1)$ 理论下限，我们必须**用空间换时间**。不在栈里单存数值，而是存入一个包裹：`(当前压入的值, 截止到目前的最小值)`。这样每次弹出栈顶，上一个状态的历史最小值就会自然“裸露”出来。

### 💻 核心代码 (Python - 严格 $O(1)$ 元组法)
```python
class MinStack(object):
    def __init__(self):
        # 栈里存放元组：(当前真实值, 历史最小值快照)
        self.stack =[]

    def push(self, val):
        if not self.stack:
            self.stack.append((val, val))
        else:
            # 当前最小值 = min(新进来的值, 之前的历史最小值)
            current_min = min(val, self.stack[-1][1])
            self.stack.append((val, current_min))
        
    def pop(self):
        # 弹出时，连同属于它的“最小值快照”一起销毁（实现状态完美回退）
        self.stack.pop()

    def top(self):
        return self.stack[-1][0]

    def getMin(self):
        # 永远在 O(1) 时间拿到栈顶元组记录的最小值
        return self.stack[-1][1]
```

### ⏱ 复杂度分析
* **时间复杂度**：所有操作严格 $O(1)$，无需任何遍历。
* **空间复杂度**：$O(N)$。用一倍的额外空间记录状态快照，换取了时间的绝对极致。

## 🟡 3. 力扣 394. 字符串解码 (嵌套结构的降维解析)

### 📝 解题思路
遇到形如 `3[a2[c]]` 的嵌套解密，本质上是**主线任务与副本任务**的切换。
1. 遇到 `[`，必须**存档（保存现场）**：把主线当前的倍数和已拼装的字符串压入栈，重置变量准备进副本。
2. 遇到 `]`，必须**读档（恢复现场）**：从栈顶取出主线的倍数和历史字符串，把刚打完的副本结果翻倍后拼接回去。

### 🚀 优化过程 (系统调用栈与递归的等价性)
* 嵌套问题的处理本质是**系统调用栈（Call Stack）**的模拟。
* 不仅可以使用显式的栈数据结构去迭代（不会爆栈，控制力强），还可以直接利用编程语言底层的**递归（Recursion）**机制隐式解题。两者在数学和可计算性上是完全等价的。

### 💻 核心代码 (Python - 迭代显式栈)
```python
class Solution(object):
    def decodeString(self, s):
        stack =[]
        res = ""     # 当前正在构建的字符串
        multi = 0    # 当前倍数
        
        for char in s:
            if char.isdigit():
                # 处理多位数字 (坑点：不能只用 int(char))
                multi = multi * 10 + int(char)
            elif char == '[':
                # 存档：遇到 '['，将外层进度压入栈，并清空当前变量打副本
                stack.append((res, multi))
                res, multi = "", 0
            elif char == ']':
                # 读档：副本打完，弹出外层进度进行拼接
                last_res, cur_multi = stack.pop()
                res = last_res + cur_multi * res
            else:
                res += char
                
        return res
```

### ⏱ 复杂度分析
* **时间复杂度**：$O(N)$（严格来说是解码后字符串的长度），因为需要执行对应的字符串拼接操作。
* **严格空间复杂度（辅助空间）**：**$O(N)$。** 空间复杂度严格取决于栈的**最大深度**（即 `[` 的最大嵌套层数）。最坏情况下（例如 `1[1[1[a]]]`），深度与字符串长度呈线性关系 $O(N)$；最好情况平铺时为 $O(1)$。

## 🧠 终极总结：关于“栈”的解题心法 (Stack Mindset)

做完这三道题，在面试中遇到“栈”相关的问题，请立刻条件反射出以下三种直觉：

1. **对称消除直觉**：
   凡是带有“匹配”、“抵消”、“连连看”性质的题目（如有效括号、消除相邻重复字母），直接掏出栈。**核心逻辑：进栈前跟栈顶比对，配对就 `pop`，不配对就 `push`。**
2. **状态快照直觉（时光倒流）**：
   凡是需要在执行删除/回退操作时，还要维持某个全局极值或状态的题目（如最小栈）。**核心逻辑：不要单存数据，要存 `(数据, 当前状态)` 的元组。让状态与数据强绑定，同生共死。**
3. **嵌套与递归直觉（保存/恢复现场）**：
   凡是带有“括号嵌套”、“计算器解析”、“深层遍历”的题目（如字符串解码）。**核心逻辑：遇到左侧标志压栈存档，清空变量；遇到右侧标志弹栈读档，组装数据。** 记住：所有能用递归解决的问题，必定能用显式栈改写！



# 🚀 算法精进笔记：单调栈 (Monotonic Stack) 降维打击

> **💡 核心心法**：单调栈的本质是**“跨越时空的状态清算”**。
> 当我们遇到“向左/向右找第一个比我大/小的元素”时，无脑祭出单调栈。
> **核心运作机制**：把暂时找不到答案的元素压入栈中（存档排队），一旦遇到能打破僵局的“终结者”，立刻触发 `while` 循环，将栈内所有满足条件的元素集体弹出（回退清算）！

---

## 🟢 1. 力扣 739. 每日温度 (单调栈标准模板)

### 📝 解题思路 (寻找下一个更大元素)
暴力法每次都要向后看，耗时 $O(N^2)$。
单调栈思路：维护一个**单调递减栈**（栈底热，栈顶冷）。栈里存放的是**“还没等到升温日子的【索引】”**。
*   **不够热**：当前温度 $\le$ 栈顶温度，说明没等到升温，当前日子进栈排队。
*   **足够热**：当前温度 $>$ 栈顶温度，**清算时刻！** 栈顶的日子终于等到了升温，弹出栈顶，计算天数差（当前索引 - 栈顶索引），然后继续用当前温度去敲下一个栈顶的门。

### 💻 核心代码 (Python)
```python
class Solution(object):
    def dailyTemperatures(self, temperatures):
        n = len(temperatures)
        ans = [0] * n  # 默认0，等不到升温就是0
        stack =[]     # 存放未找到升温日期的索引
        
        for i in range(n):
            # 遇到终结者：当前温度打破了栈顶的低温僵局，触发集体清算
            while stack and temperatures[i] > temperatures[stack[-1]]:
                prev_index = stack.pop()          # 取出栈顶
                ans[prev_index] = i - prev_index  # 记录等待天数
                
            stack.append(i) # 清算完毕，当前日子入栈等待它的缘分
            
        return ans
```

### ⏱ 复杂度与疑难解析
*   **时间复杂度：严格 $O(N)$**。虽然 `for` 里套了 `while`，但每个元素**最多进栈 1 次，出栈 1 次**，总操作次数不超过 $2N$。
*   **空间复杂度：$O(N)$**。最坏情况下（温度一直下降），所有元素都在栈中。

## 🔴 2. 力扣 84. 柱状图中最大的矩形 (单调栈最终 Boss)

### 📝 解题思路 (寻找左右第一个更小的元素)
不要去找矩形，而去**遍历每一根柱子，强制把它当作矩形的高度**。
此时，矩形的宽度取决于：它能向左/右延伸多远？
*   **右边界**：右边第一个比它矮的柱子（就是把它弹出去的那个终结者）。
*   **左边界**：左边第一个比它矮的柱子（就是它在栈里踩着的那根柱子）。
维护一个**单调递增栈**，一旦遇到比栈顶矮的柱子，触发清算，计算栈顶柱子的最大面积！

### 🧠 深度疑难杂点剖析 (全网最透彻解析)

#### 疑难一：首尾为什么要加“哨兵 (Sentinel)”？
*   **尾部加哨兵**：如果原数组是持续递增的，栈内元素永远遇不到“比自己矮”的终结者，导致最后留在栈里不清算。尾部加一个极小值，能像秋风扫落叶一样，在最后一步把栈内所有柱子强制清算。
*   **首部加哨兵**：当遇到极小的终结者时，栈会被抽空。首部放一个极小值永远垫底，可以避免 `stack[-1]` 发生数组越界报错，彻底消灭 `if not stack` 的恶心判断。

#### 疑难二：取值范围是 `0 <= heights[i]`，加 `0` 还是加 `-1`？
*   **模板的惰性平衡**：写 `[0] + heights +[0]` 时，如果数组全是 `0`，因为 `0 < 0` 为假，根本不会触发清算。但恰巧 `0 * 宽 = 0`，不计算也不影响正确结果（歪打正着）。
*   **绝对严谨的数学闭环**：为了强行触发所有元素的清算，且防止左边界被踢出导致越界，**最优解是使用 `[-1] + heights + [-1]`**。因为 `-1` 是绝对的谷底，能严格清算包含 `0` 在内的所有合法高度，且左侧 `-1` 永远不会被右侧 `-1` 踢出（`-1 < -1` 为假）。

#### 疑难三：铁血证明 —— 为什么 `stack[-1]` 绝对是“左边第一个比它矮的”？
假设 A 进栈踩在了 L 身上（`stack = [..., L, A]`），为什么 L 和 A 中间绝对没有比 A 矮的柱子？
*   **反证法**：假设中间有个叛徒 X 比 A 矮（`X < A`）。
*   既然 X 比 A 矮，且 X 在 A 之前遍历，那么 A 进栈时，X 要么还在栈里，要么被别人（更矮的 Y）踢出去了。
*   这意味着，在 A 敲门时，栈顶必然躺着一个 $\le X$ 的幸存者。
*   因为 `X < A`，所以这个幸存者绝对 `< A`。
*   如果真的有这么一个幸存者，A 进栈时就应该踩在这个幸存者头上，**绝对轮不到 A 去踩 L！**
*   **结论**：既然 A 结结实实地踩在了 L 身上，说明 A 把中间所有的柱子都“削平/踢出”了。能被 A 踢出，说明它们都比 A 高。因此，L 绝对是 A 左边**第一个**比它矮的！

#### 疑难四：遇到连在一起的相等高度（如 `[5, 5]`）怎么算？
*   按照 `<` 的逻辑，相等的柱子会全部进栈。
*   清算时，后面的 `5` 算出的左边界是前面的 `5`，算出的宽度只有 1（局部错误压缩）。
*   **破局**：但这丝毫不影响最终的最大面积！因为紧接着，最前面的 `5` 也会被弹出清算，它的左边界会正确地跨越所有相等的兄弟，算出**囊括所有人的完美最大宽度**。局部不准确，但全局最大值绝对正确！

### 💻 强迫症狂喜的绝对严谨版代码 (Python)
```python
class Solution(object):
    def largestRectangleArea(self, heights):
        # 👑 极客优化：使用双 -1 作为绝杀哨兵
        # 左 -1：永远垫底，保障 stack[-1] 永不越界。
        # 右 -1：终极死神，比数组里任何元素都小，保证结束前绝对清算所有柱子！
        heights = [-1] + heights + [-1]
        n = len(heights)
        
        stack = [0]  # 先把左哨兵的索引 0 压入栈底
        max_area = 0 
        
        for i in range(1, n):
            # 遇到更矮的柱子，说明栈顶柱子的“右边界”确定了
            while heights[i] < heights[stack[-1]]:
                cur_height = heights[stack.pop()]  # 1. 确定高度
                left_index = stack[-1]             # 2. 绝对左边界
                cur_width = i - left_index - 1     # 3. 计算宽度
                max_area = max(max_area, cur_height * cur_width) # 4. 结算面积
            
            stack.append(i) # 踩在比自己矮的柱子身上，安心进栈
            
        return max_area
```

### ⏱ 复杂度分析
*   **时间复杂度**：$O(N)$。每根柱子严格进栈 1 次，出栈 1 次，执行效率极致。
*   **空间复杂度**：$O(N)$。使用了辅助栈存储索引，最坏情况下呈严格单调递增，占用 $O(N)$ 空间。
