# 🚀 算法精进笔记：贪心算法 (Greedy) 降维打击与思维跃迁

> **💡 核心心法**：
> 贪心算法的本质是**“局部最优解推导全局最优解”**。
> **贪心快但不一定正确；能用贪心的题，一般都是最优解法里最快的。DP 稳但相对慢。**
> 贪心：每步局部最优，不回头，只做一次选择。
> DP：保存所有子问题结果，选择最优子结构组合。

---

## 🟢 一、 贪心基石：买卖股票的最佳时机 (力扣 121)

### 📝 暴力解法的痛点（为什么我们需要贪心？）
假设股票价格是 `prices =[7, 1, 5, 3, 6, 4]`。
**最本能的暴力法**：两层 `for` 循环。挑一天买入，再把后面所有的日子都看一遍，算出所有可能的利润，找最大值。
*   **痛点**：时间复杂度 $O(N^2)$。如果有 10 万天的数据，直接超时（Time Limit Exceeded）。

**破局思考**：我们真的需要往后看每一天吗？
如果我强制规定**“今天必须卖出”**，那我怎么才能赚得最多？
答案极其简单：**我只要知道在今天之前，哪一天的股票最便宜，然后在那天买入就行了！**

### 🧠 贪心算法的核心心法：极致的“目光短浅”
作为一个贪婪的炒股人，我每天只需要**贪婪地记住两件事**：
1.  **历史最低价 (`min_price`)**：只要今天比过去都便宜，我就贪婪地把它记作最低价。
2.  **历史最高利润 (`max_profit`)**：如果今天卖出，利润 = 今天价格 - 历史最低价。如果大于历史最高利润，我就贪婪地更新！

### 💻 极度优雅的核心代码 (Python)
```python
class Solution(object):
    def maxProfit(self, prices):
        min_price = float('inf')
        max_profit = 0
        
        for price in prices:
            # 每天都在贪婪地做两件事，一次遍历，不走回头路：
            min_price = min(min_price, price)                # 1. 刷新历史底价
            max_profit = max(max_profit, price - min_price)  # 2. 刷新最高利润
            
        return max_profit
```
*   **复杂度**：时间 $O(N)$，空间 $O(1)$。我们用 $O(1)$ 的空间，完美压缩了 DP 本来需要 $O(N)$ 数组才能记录的状态！

## 🟡 二、 跳跃游戏 (力扣 55) —— 贪心连通性检测

### 📝 解题思路 (维护最大覆盖范围)
面对“能否到达终点”的问题，最怕陷入“当前该跳几步”的局部泥潭。
**降维打击思路**：我们只维护一个变量 `cover`（当前能到达的最远索引）。遍历数组，只要当前位置 `i` 在我的覆盖范围内（`cover >= i`），我就尝试用当前位置的弹跳力去更新 `cover = max(cover, i + nums[i])`。

### 🚀 极客优化 (提前开香槟与深渊拦截)
*   **提前下班**：一旦发现 `cover >= n - 1`，火力已经覆盖终点，直接 `break` 返回 `True`。
*   **深渊拦截**：如果遍历到的索引 `i > cover`，说明前面无论怎么跳，都跨不过某个大坑。直接 `break` 返回 `False`。

### 💻 核心代码 (Python)
```python
class Solution(object):
    def canJump(self, nums):
        n = len(nums)
        cover = 0
        for i, step in enumerate(nums):
            if cover >= i and cover < n - 1:
                cover = max(cover, i + step)
            else:
                break
        return cover >= n - 1
```
*   **复杂度**：时间 $O(N)$，空间 $O(1)$。

## 🔴 三、 跳跃游戏 II (力扣 45) —— 波纹扩散与延迟清算

### 📝 解题思路 (隐式 BFS / 寻找最小跳跃次数)
不仅要能到终点，还要次数最少。此时我们不能一发现更远的地方就加步数，而是要把跳跃看作**“水面上荡开的一圈圈波纹”**。
需要维护三个灵魂变量：`times` (起跳次数)，`end` (当前波纹的物理极限边界)，`max_pos` (探路发现的下一跳最远火力点)。

### 🧠 灵魂顿悟 (破除“在 i 处起跳”的幻觉)
我们在遍历时疯狂更新 `max_pos`，但**先不跳**！
当且仅当走到了 `i == end`（摸到结界边缘）时，我们才**被迫**起跳：`times += 1`，并将新结界更新为 `end = max_pos`。
**🔥 顶级认知**：此时的 `times += 1`，**绝不意味着我们在 `i` 处起跳！** 真正的起跳点是之前路过的某个创造了 `max_pos` 的位置 `j`。贪心的霸道之处在于：**我们根本不关心 `j` 到底在哪，我们只“窃取” `j` 带来的最远距离作为下一跳的边界！**

### 💻 核心代码 (Python)
```python
class Solution(object):
    def jump(self, nums):
        n = len(nums)
        if n <= 1: return 0 
            
        times, end, max_pos = 0, 0, 0

        # ⚠️ 绝不遍历最后一个元素 (range(n-1))
        for i in range(n - 1):
            max_pos = max(max_pos, i + nums[i]) # 漫步结界，记录最远火力点
            
            if i == end:         # 动能耗尽，被迫起跳
                times += 1       
                end = max_pos    # 开启下一圈新波纹的结界
                if end >= n - 1: # 提前下班
                    break
        return times
```
*   **复杂度**：时间 $O(N)$，空间 $O(1)$。

## 🟡 四、 划分字母区间 (力扣 763) —— 双流派贪心切割

这道题完美展示了在面临“局部约束”时，我们可以通过**“状态清零”**或**“结界覆盖”**两种截然不同的贪心模型来破局！

### 🗡️ 流派一：我的首创“债务结清法” (状态引用计数模型)
**📝 核心思路**：跳出坐标的限制，将字符数量视为“债务”。
1. **摸底**：先遍历一遍，统计每个字符的总出现次数（总债务）。
2. **入场与还债**：第二遍遍历，遇到字符就把债务减 1。并将字符加入当前观察集合 `cur_str`。
3. **彻底清账**：一旦某个字符的债务归 0，说明它以后绝迹了！从 `cur_str` 中踢出。
4. **完美切割**：当 `cur_str` 变为空集时，说明当前片段里的所有人都“无债一身轻”（后续再也不会出现），果断切下一刀！

**💻 极致优化代码 (纯数组常数级 $O(1)$ 寻址)：**
```python
class Solution(object):
    def partitionLabels(self, s):
        # 1. 极客优化：用长度26的数组代替哈希表，ASCII偏移量直接寻址，速度拉满
        freq_count = [0] * 26
        for char in s:
            freq_count[ord(char) - 97] += 1

        res=[]
        cur_count = 0
        cur_str = set()

        # 2. 动态还债与清算
        for char in s:
            cur_count += 1
            cur_str.add(char)  # 拉入当前结界
            freq_count[ord(char) - 97] -= 1  # 偿还一次债务
            
            if freq_count[ord(char) - 97] == 0:
                cur_str.remove(char) # 债务清零，踢出结界
                if not cur_str:      # 结界空了！所有人后续都不会再出现了
                    res.append(cur_count)
                    cur_count = 0
        return res
```

### 🛡️ 流派二：官方标准解“结界扩张法” (跳跃游戏模型)
**📝 核心思路**：你会发现，这其实就是**《45. 跳跃游戏 II》的翻版**！
如果当前片段包含了字符 `'a'`，而 `'a'` 最后一次出现在索引 8，那么**当前切割的边界至少要延伸到 8**！
1. **获取最远射程**：用字典记录每个字符最后一次出现的索引。
2. **刷新结界**：维护当前片段的最远边界 `end`。每遇到一个字符，就试图去扩张结界：`end = max(end, 字符最后出现的索引)`。
3. **触发切割**：当你走到 `i == end` 时，说明结界内所有的字符，其最远射程都没超出这个结界。动能耗尽，完美切割！

**💻 核心代码 (Pythonic极简版)：**
```python
class Solution(object):
    def partitionLabels(self, s):
        # 字典推导式：同名键不断覆盖，留下的天然就是最后一次出现的索引
        last_occurrence = {char: i for i, char in enumerate(s)}
        
        res =[]
        start = 0  # 当前片段的起始索引
        end = 0    # 当前片段的物理极限边界
        
        for i, char in enumerate(s):
            # 用当前字符的最远射程，贪婪地去撑开结界
            end = max(end, last_occurrence[char])
            
            # 当走到结界边缘时，触发清算切割
            if i == end:
                res.append(end - start + 1) # 记录当前段长度
                start = i + 1               # 开启下一段
                
        return res
```

### ⚔️ 核心思路深度对比与总结
| 维度 | 债务结清法 (我的首创) | 结界扩张法 (官方跳跃模型) |
| :--- | :--- | :--- |
| **思维模型** | **状态维护**。关注每一个字符剩余的数量是否清零。 | **贪心覆盖**。关注每个字符能辐射到的最远物理距离。 |
| **切割时机** | 当前监控集合为空集时切割。 | 当 `i == end`（走到边界）时切割。 |
| **时间复杂度** | **$O(N)$**。遍历两遍字符串。 | **$O(N)$**。遍历两遍字符串。 |
| **空间复杂度** | **$O(\Sigma)$**。固定 26 长度数组 + 临时 Set（开销极小）。 | **$O(\Sigma)$**。最多容纳 26 个键的哈希表。 |
| **架构领悟** | 熟练利用 `set` 和数组代替高开销对象，工程常数极佳，是独创的计算机垃圾回收思维。 | 万物互联！**跳跃游戏中的“寻找下一跳极限”**在字符串切割中完美复现，算法底层逻辑的彻底贯通！ |
