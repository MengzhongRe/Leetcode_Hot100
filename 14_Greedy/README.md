### 一、 暴力解法的痛点（为什么我们需要贪心？）

假设股票价格是 `prices =[7, 1, 5, 3, 6, 4]`。
**最本能的暴力法**：两层 `for` 循环。挑一天买入，再把后面所有的日子都看一遍，算出所有可能的利润，找最大值。
*   **痛点**：时间复杂度 $O(N^2)$。如果有 10 万天的数据，直接超时（Time Limit Exceeded）。

**破局思考**：我们真的需要往后看每一天吗？
如果我强制规定**“今天必须卖出”**，那我怎么才能赚得最多？
答案极其简单：**我只要知道在今天之前，哪一天的股票最便宜，然后在那天买入就行了！**

---

### 二、 贪心算法的核心心法：极致的“目光短浅”

所谓“贪心算法”，本质上就是**“只顾眼前的绝对局部最优，一步步推导出全局最优”**。

在这道题里，作为一个贪婪的炒股人，我每天只需要**贪婪地记住两件事**（维护两个变量）：
1.  **历史最低价 (`min_price`)**：只要今天比过去都便宜，我就贪婪地把它记作最低价，作为未来的潜在买入点。
2.  **历史最高利润 (`max_profit`)**：如果今天不买入，而是卖出，我就贪婪地算一下“今天的价格 - 历史最低价”。如果这个差价大于我之前赚过的钱，我就贪婪地更新我的最高利润！

#### 🎬 动画级推演：`[7, 1, 5, 3, 6, 4]`
*   **初始状态**：`min_price = 无穷大`，`max_profit = 0`。
*   **第 1 天 (7)**：太贵了，但没有历史对比，只能记下 `min_price = 7`。利润 = 0。
*   **第 2 天 (1)**：哇！1 块钱！比历史最低价 7 还便宜！贪心发作，更新 `min_price = 1`。利润依然 = 0（你总不能按 7 块买 1 块卖吧）。
*   **第 3 天 (5)**：没 1 块钱便宜。那如果今天卖呢？利润 = `5 - 1 = 4`。比之前的利润 0 大！贪心发作，更新 `max_profit = 4`。
*   **第 4 天 (3)**：没 1 块钱便宜。今天卖的话利润 = `3 - 1 = 2`。不如 4 赚得多，不管它。
*   **第 5 天 (6)**：没 1 块钱便宜。今天卖的话利润 = `6 - 1 = 5`。哇！赚了 5 块！贪心发作，更新 `max_profit = 5`。
*   **第 6 天 (4)**：没 1 块钱便宜。卖的话利润 `4 - 1 = 3`。不管它。

遍历结束！最高利润 `5`。我们**只遍历了一遍数组（$O(N)$）**，就找出了最高利润！

---

### 三、 极度优雅的核心代码 (Python)

贪心算法的代码往往短得令人发指，因为它没有任何复杂的数据结构（连栈和堆都不需要），只需要极其纯粹的逻辑比对。

利用 Python 内置的 `min()` 和 `max()` 函数，我们可以把代码写得极具数学美感：
```python
class Solution(object):
    def maxProfit(self, prices):
        min_price = float('inf')
        max_profit = 0
        
        for price in prices:
            # 每天都在贪婪地做两件事：
            min_price = min(min_price, price)                # 1. 刷新历史底价
            max_profit = max(max_profit, price - min_price)  # 2. 刷新最高利润
            
        return max_profit
```

---

### 四、 复杂度分析

*   **时间复杂度**：**$O(N)$**。就像开着一辆车从头到尾把数组扫了一遍，每个元素只看了一次，没有任何回头路。
*   **空间复杂度**：**$O(1)$**。只用了 `min_price` 和 `max_profit` 两个变量记录状态，没有开辟任何数组、栈或堆，极致省内存。

---

### 👑 架构师视角：贪心 vs 动态规划 (DP)

这道题其实是**动态规划（Dynamic Programming, DP）**的一维极简版！
如果你在这个时候能把这道题和 DP 联系起来，后面的硬核股票题你将如履平地。

在 DP 的视角下，状态转移方程是这样的：
`第 i 天的最大利润 = max(第 i-1 天的最大利润, 第 i 天卖出的利润)`

为了算出“第 i 天卖出的利润”，我们就必须知道“第 i 天之前的最低买入价”。
所以我们用一个变量 `min_price` 滚动记录历史最低价，用 `max_profit` 滚动记录最大利润。**我们用 $O(1)$ 的空间，完美压缩了 DP 本来需要 $O(N)$ 数组才能记录的状态！**

这就是贪心算法的魅力：**只要局部最优解（一直记录最低价）能够无条件地推导出全局最优解（最高利润），贪心就是成立的！**


贪心：每步局部最优，不回头，只做一次选择
DP：保存所有子问题结果，选择最优子结构组合
**贪心快但不一定正确；能用贪心的题，一般都是最优解法里最快的。DP 稳但相对慢**

# 🚀 算法精进笔记：贪心算法降维打击 (跳跃游戏双璧)

> **💡 核心心法**：
> 贪心算法的本质是**“局部最优解推导全局最优解”**。
> 在跳跃游戏系列中，我们**绝不纠结于“每一步具体踩在哪块石头上”**，而是把视角拉高到上帝视角，专注于维护**「最大火力覆盖范围」**。只要终点在我的射程之内，我就一定能到达！

---

## 🟢 一、 力扣 55. 跳跃游戏 (贪心入门与连通性检测)

### 📝 解题思路 (维护最大覆盖范围)
面对“能否到达终点”的问题，最怕陷入“当前该跳几步”的局部泥潭。
**降维打击思路**：我们只维护一个变量 `cover`（当前能到达的最远索引）。遍历数组，只要当前位置 `i` 在我的覆盖范围内（`cover >= i`），我就尝试用当前位置的弹跳力去更新 `cover = max(cover, i + nums[i])`。

### 🚀 极客优化 (提前开香槟与深渊拦截)
*   **提前下班**：一旦发现 `cover >= n - 1`，说明火力已经覆盖终点，后面哪怕有上百万个石头也不用看了，直接 `break` 返回 `True`。
*   **深渊拦截**：如果遍历到的索引 `i > cover`，说明前面无论怎么跳，都跨不过某个大坑（比如遇到 0）。此时继续遍历毫无意义，直接 `break` 返回 `False`。

### 💻 核心代码 (Python)
```python
class Solution(object):
    def canJump(self, nums):
        n = len(nums)
        cover = 0

        for i, step in enumerate(nums):
            # 核心剪枝：1. 必须能走到当前 i；2. 还没覆盖到终点
            if cover >= i and cover < n - 1:
                cover = max(cover, i + step)
            else:
                break
                
        # 比较表达式本身返回布尔值，极致优雅
        return cover >= n - 1
```
### ⏱ 复杂度分析
*   **时间复杂度**：严格 $O(N)$。遍历一次数组，且由于提前 `break` 机制，真实运行常数极小。
*   **空间复杂度**：$O(1)$。仅维护了一个整型变量 `cover`。

## 🔴 二、 力扣 45. 跳跃游戏 II (波纹扩散与延迟清算)

### 📝 解题思路 (隐式 BFS / 寻找最小跳跃次数)
不仅要能到终点，还要次数最少。此时我们不能一发现更远的地方就加步数，而是要把跳跃看作**“水面上荡开的一圈圈波纹”**。
我们需要维护三个灵魂变量：
1.  `times`：已经起跳的次数（波纹圈数）。
2.  `end`：当前这一跳的物理极限边界（当前波纹的结界）。
3.  `max_pos`：在结界内探路时，发现的下一跳最远火力点。

### 🧠 灵魂顿悟 (破除“在 i 处起跳”的幻觉)
我们在遍历时疯狂更新 `max_pos`，但**先不跳**！
当且仅当走到了 `i == end`（当前动能耗尽，摸到结界边缘）时，我们才**被迫**起跳：`times += 1`，并将新结界更新为 `end = max_pos`。
**🔥 顶级认知**：此时的 `times += 1`，**绝不意味着我们在 `i` 处起跳！** 真正的起跳点是之前路过的某个创造了 `max_pos` 的位置 `j`。贪心的霸道之处在于：**我们根本不关心 `j` 到底在哪，我们只“窃取” `j` 带来的最远距离作为下一跳的边界！**

### 💻 核心代码 (Python)
```python
class Solution(object):
    def jump(self, nums):
        n = len(nums)
        if n <= 1: return 0  # 边界防御：已经在终点，无需起跳
            
        times = 0
        end = 0       # 当前这一跳的极限边界
        max_pos = 0   # 探路发现的下一跳最远距离

        # ⚠️ 究极细节：绝不遍历最后一个元素 (range(n-1))
        # 因为题目保证一定能到终点。如果刚好在边界 end 到达终点 n-1，
        # 不需要再起跳，若遍历 n-1 会导致 times 错误 +1。
        for i in range(n - 1):
            # 1. 漫步结界，疯狂记录下一跳的最远火力点
            max_pos = max(max_pos, i + nums[i])
            
            # 2. 动能耗尽，摸到结界边缘，被迫起跳！
            if i == end:
                times += 1       # 结算步数 (起跳点是历史某个 j，无需深究)
                end = max_pos    # 开启下一圈新波纹的结界
                
                # 3. 极致剪枝：如果新结界已经吞噬终点，提前下班！
                if end >= n - 1:
                    break
                    
        return times
```

### ⏱ 复杂度分析
*   **时间复杂度**：严格 $O(N)$。完美的一次遍历，且内含提前 `break` 的香槟机制。
*   **空间复杂度**：严格 $O(1)$。只用了三个滚动变量。
