## 🎒 一、 0-1 背包问题 (0-1 Knapsack)

#### 1. 问题定义（物理场景）
你是一个小偷，带着一个容量为 $V$ 的背包。
面前有 $N$ 个物品，第 $i$ 个物品的重量是 $w[i]$，价值是 $v[i]$。
**核心铁律：每个物品【只有 1 件】！你对每个物品只能做两个选择：拿（1）或者 不拿（0）。**
求：背包能装下的最大价值是多少？

#### 2. 二维状态转移方程（最原始的推导）
定义 `dp[i][j]`：在前 `i` 个物品中做选择，背包容量为 `j` 时的最大价值。
面对第 `i` 个物品，你有两个选择：
*   **不拿**：容量没变，价值就是前 `i-1` 个物品的价值。$\rightarrow$ `dp[i-1][j]`
*   **拿**：前提是容量 `j` 够用（`j >= w[i]`）。腾出 `w[i]` 的空间给它，总价值变成前 `i-1` 个物品在剩余空间下的最大价值 + 当前物品价值。$\rightarrow$ `dp[i-1][j - w[i]] + v[i]`

**综合方程**：`dp[i][j] = max(dp[i-1][j], dp[i-1][j - w[i]] + v[i])`

#### 3. 空间降维打击（一维数组）与“逆序的奥秘”
注意到 `dp[i]` 永远只依赖于 `dp[i-1]`（上一层的数据）。我们完全可以把二维数组压缩成一个一维数组 `dp[j]`！
压缩后的方程长这样：`dp[j] = max(dp[j], dp[j - w[i]] + v[i])`。

🚨 **致命考点：为什么一维 0-1 背包的内层循环必须【逆序遍历】（从大到小）？**
假设物品重量为 1，价值为 10。
如果**正序遍历**（$j$ 从 1 到 5）：
*   算 `dp[1]` 时，拿了该物品，`dp[1] = dp[0] + 10 = 10`。
*   算 `dp[2]` 时，`dp[2] = max(dp[2], dp[2-1] + 10) = max(0, dp[1] + 10) = 20`！
**惨案发生！** 算 `dp[2]` 时用到的 `dp[1]`，是刚刚在这一轮被更新过的值！这意味着**同一个物品被拿了两次**！这违背了 0-1 背包“每个物品只有 1 件”的铁律。

**破局**：如果**逆序遍历**（$j$ 从 5 到 1）：
算 `dp[5]` 时用到的 `dp[4]`，绝对是上一层留下的“旧数据”（因为 4 还没被更新）。完美保证了每个物品只被拿一次！

**💻 0-1 背包标准模板：**
```python
# 外层遍历物品，内层【逆序】遍历背包容量
for i in range(N):
    for j in range(V, w[i] - 1, -1): # 逆序！
        dp[j] = max(dp[j], dp[j - w[i]] + v[i])
```

### ♾️ 二、 完全背包问题 (Unbounded Knapsack)

#### 1. 问题定义（物理场景）
同样的小偷，同样的背包。
**核心铁律改变：每个物品有【无限件】！只要背包能装下，同一个物品你想拿多少件就拿多少件。**

#### 2. 状态转移方程的变化
既然可以无限拿，那么在考虑第 `i` 个物品时，如果决定拿它，拿完之后**我依然可以继续拿第 `i` 个物品**！
所以二维方程变成了：
`dp[i][j] = max(dp[i-1][j], dp[i][j - w[i]] + v[i])`
*(注意看第二项，0-1背包是 `dp[i-1]`，这里变成了 `dp[i]`！)*

#### 3. 空间降维打击与“正序的奥秘”
同样压缩成一维数组：`dp[j] = max(dp[j], dp[j - w[i]] + v[i])`。
（你会惊恐地发现，压缩后的一维状态转移方程，0-1 背包和完全背包**长得一模一样**！）

🚨 **致命考点：为什么一维完全背包的内层循环必须【正序遍历】（从小到大）？**
刚才在 0-1 背包里导致“惨案”的正序遍历，在这里变成了**天造地设的完美机制**！
算 `dp[2]` 时用到了刚刚更新的 `dp[1]`，这意味着我拿了一个物品后，在这个基础上**又拿了一个同样的物品**。这完完全全就是“完全背包”允许物品无限次拿取的物理定义！

**💻 完全背包标准模板：**
```python
# 外层遍历物品，内层【正序】遍历背包容量
for i in range(N):
    for j in range(w[i], V + 1): # 正序！
        dp[j] = max(dp[j], dp[j - w[i]] + v[i])
```

### 🎯 四、 背包问题的四大核心题型变种（LeetCode 实战罗盘）

背包问题之所以难，是因为面试官很少直接问“最大价值”。他们会把问题包装成各种花样。只要你认准下面这 **4 种数学符号**，所有背包题秒杀！

#### 变种 1：最值问题 (求最大/最小)
*   **特征**：求装满背包的最大价值、最少硬币数。
*   **公式**：`dp[j] = max/min(dp[j], dp[j - w[i]] + v[i])`
*   **代表题**：
    *   【完全背包】**力扣 322. 零钱兑换**（求凑成总金额的**最少**硬币个数。这就是你昨天做的 279 题《完全平方数》的亲兄弟！）
    *   【0-1背包】**力扣 474. 一和零**（二维费用的 0-1 背包）。

#### 变种 2：存在性问题 (求 True/False)
*   **特征**：问能不能恰好装满背包。
*   **公式**：`dp[j] = dp[j] or dp[j - w[i]]`
*   **代表题**：
    *   【0-1背包】**力扣 416. 分割等和子集**（把数组分成两半，和相等 $\rightarrow$ 背包容量为 `sum/2`，问能不能装满）。

#### 变种 3：组合数问题 (求方案数，不强调顺序)
*   **特征**：问装满背包有几种方法。（例如：1+2 和 2+1 算同一种方法）。
*   **公式**：`dp[j] += dp[j - w[i]]`
*   **灵魂细节**：**外层遍历物品，内层遍历容量！**
*   **代表题**：
    *   【完全背包】**力扣 518. 零钱兑换 II**（求硬币凑成总额的组合数）。

#### 变种 4：排列数问题 (求方案数，强调顺序)
*   **特征**：问装满背包有几种方法。（例如：1+2 和 2+1 算作**两种**不同的方法）。
*   **公式**：`dp[j] += dp[j - w[i]]`
*   **灵魂细节（地狱级考点）**：**外层遍历容量，内层遍历物品！**（只有互换循环顺序，才能让同一个物品在不同的容量阶段被反复排列组合）。
*   **代表题**：
    *   【完全背包】**力扣 377. 组合总和 Ⅳ**（求组成目标数的排列个数）。

### 终极领悟

你昨天独立解出的《279. 完全平方数》，正是上述的**变种 1（完全背包的最值问题）**！
* 物品是：1, 4, 9, 16...（无限使用 $\rightarrow$ 完全背包）。
* 容量是：`n`。
* 公式是：`dp[j] = min(dp[j], dp[j - square] + 1)`。
* 循环方向：正序！

把这份“背包问题全景图”装进脑子里，以后只要看到题目里有**“给定一个集合，求组合 / 求最值 / 求能否凑成”**的字眼，大脑立刻启动这张图纸：
1. 先问自己：元素能重复用吗？（决定 0-1 还是 完全）
2. 再问自己：求什么？（决定状态方程是 `max`, `or`, 还是 `+=`）
3. 最后问自己：顺序敏感吗？（决定 `for` 循环谁在外谁在内）

## 背包问题的内外层遍历顺序解析

核心结论：
**外层物品、内层容量，是所有背包问题的“正统亲妈”！但这并不是唯一的写法。内外层循环能不能调换，完全取决于你要求的是【最值（Min/Max）】还是【方案数（组合/排列）】！**

我们从两个最本质的维度，彻底把你这个疑问打穿：

---

### 🧬 本质一：从“二维推导一维”的血统论（为什么它是正统？）

在背包问题的最底层，也就是最初始的二维状态转移方程中，我们的定义是：
`dp[i][j]` = 考虑**前 `i` 个物品**，凑成容量 `j` 的结果。

注意这个定义的物理意义：**它是一个严格的“阶段性决策”过程。**
*   **阶段 1**：我只看着第 1 个物品，把容量从 0 到 $V$ 填满。
*   **阶段 2**：我看着前 2 个物品，利用阶段 1 的历史数据，把容量从 0 到 $V$ 填满。
*   **阶段 3**：我看着前 3 个物品……

在这个二维矩阵里，**“物品 `i`” 代表的是矩阵的“行（Row）”，“容量 `j`” 代表的是矩阵的“列（Col）”。**
按照正常人类填表格的逻辑，我们肯定是**“一行一行地填”**。因为第 `i` 行的计算，严格依赖于第 `i-1` 行的数据。
**“一行一行地填”，翻译成代码，就是：外层循环遍历行（物品），内层循环遍历列（容量）！**

所以，当我们把二维数组压缩成一维数组 `dp[j]` 时，为了继承这种“阶段性演进”的纯正血统，我们自然而然地保留了**“外层物品，内层容量”**的习惯。这就是它的本质起源。

---

### ⚖️ 本质二：排列与组合的“因果律”（决定生死的循环顺序）

如果只是习惯也就罢了，但在有些题里，如果你敢把内外层循环换过来，代码直接报错！这就涉及到了背包问题的终极心法：**组合（Combination）与排列（Permutation）的区别。**

假设我们有硬币（物品）：`[1, 2]`。目标容量是 `3`。

#### 1. 🟢 外层遍历【物品】，内层遍历【容量】 $\rightarrow$ 得到的是【组合数】
*   **代码行为**：外层先固定物品 `1`，内层跑完所有容量；外层再固定物品 `2`，内层跑完所有容量。
*   **物理意义**：这意味着，一旦我处理完了物品 `1`，以后**再也见不到**物品 `1` 了！我只能在已经有 `1` 的基础上，往里面加 `2`。
*   **产生的序列**：只会产生 `{1, 1, 1}` 和 `{1, 2}`。
*   **绝对不可能产生 `{2, 1}`！** 因为物品是按顺序来的，`2` 放进去之后，不可能再回头去放 `1`！这在数学上叫**无序的组合**。

#### 2. 🔴 外层遍历【容量】，内层遍历【物品】 $\rightarrow$ 得到的是【排列数】
*   **代码行为**：外层先固定容量 `1`，内层尝试放入物品 `1` 和 `2`；外层接着固定容量 `2`，内层又去尝试放入物品 `1` 和 `2`……
*   **物理意义**：这意味着，在每一个容量阶段，**所有的物品都在我面前，我都有平等的权利去挑选它们！**
*   **产生的序列**：凑成容量 3 时，我可以通过 `dp[2] + 物品1` 得到，也可以通过 `dp[1] + 物品2` 得到。
*   所以，它不仅会产生 `{1, 2}`，还会产生 `{2, 1}`！这在数学上叫**有顺序的排列**。

*(📝 刷题心法：力扣 518 题《零钱兑换 II》求组合数，必须外层物品；力扣 377 题《组合总和 IV》求排列数，必须外层容量！)*

如果在面试中，你和面试官聊到了背包问题，你可以抛出这段“绝杀降维论”：

> “在动态规划中，关于外层遍历物品还是内层遍历物品，本质上取决于两个维度：
> 
> 第一：**状态依赖的渊源**。背包问题脱胎于二维状态 `dp[i][j]`，按行（物品）推进是符合无后效性最自然的方式，所以它是标准模板。
> 
> 第二：**排列与组合的数学性质**。如果题目要求计算**方案数**：
> *   外层物品、内层容量 $\rightarrow$ 求解的是**组合数**（严格按物品顺序入包，不重复）。
> *   外层容量、内层物品 $\rightarrow$ 求解的是**排列数**（每种容量下都重新审视所有物品，产生各种顺序）。
> 
> 但是，如果题目像《完全平方数》或《零钱兑换》一样，只求**极值（Max/Min）**，那么排列和组合的长度/价值是一样的。此时，**两个循环谁在外面、谁在里面，理论上是等价的，都可以得出正确答案！** 只不过为了保持思维的一致性，我们通常统一套用‘外层物品’的标准背包模板。”

## 外什么0-1背包问题必须是外层遍历物品，内层遍历背包？而完全背包问题（求极值）两者都可以？

### 🚨 一、 第一行（0-1 背包）：为什么绝对不能换？（毁灭性灾难）

**假设我们强行把 0-1 背包写成：外层遍历【容量 $j$】，内层遍历【物品 $i$】。**
代码长这样：
```python
# 灾难级 0-1 背包写法
for j in range(1, V + 1):          # 外层：容量从 1 到 V
    for i in range(N):             # 内层：遍历所有物品
        if j >= w[i]:
            dp[j] = max(dp[j], dp[j - w[i]] + v[i])
```

**【案发现场推演】**
假设有一个物品 A：重量 `w = 2`，价值 `v = 10`。
*   当外层容量 `j = 2` 时：内层遍历到物品 A，`dp[2] = max(0, dp[0] + 10) = 10`。**（物品 A 被放入了背包！）**
*   当外层容量继续涨，走到 `j = 4` 时：内层再次遍历到物品 A，此时它去查 `dp[j - w[i]]`，也就是查 `dp[2]`。
*   它发现 `dp[2] = 10`，于是开心地计算：`dp[4] = dp[2] + 10 = 20`！

**💥 致命错误发生了！**
在计算 `dp[4]` 的时候，它把物品 A **又装了一次**！
这就完全破坏了 0-1 背包**“每个物品只能用一次”**的物理铁律！它硬生生被你写成了“完全背包”！

**为什么标准写法（外物品、内容量逆序）就不会错？**
因为外层是物品，意味着**每个物品我这辈子只处理一次**。处理完了，我就再也不看它了。这就从物理机制上绝对保证了 0-1 背包的唯一性。

---

### 👑 二、 第二行（完全背包求最值）：为什么可以换？（殊途同归的奇迹）

**假设我们把完全背包写成：外层遍历【容量 $j$】，内层遍历【物品 $i$】。**
代码长这样：
```python
# 完全可以的写法
for j in range(1, V + 1):          # 外层：容量从小到大
    for i in range(N):             # 内层：遍历所有物品
        if j >= w[i]:
            dp[j] = max(dp[j], dp[j - w[i]] + v[i])
```

**【奇迹发生推演】**
*   正如我们刚才在灾难推演里看到的，这种“外层容量、内层物品”的写法，天然会导致**同一个物品被多次放入背包**。
*   **但是！这不正是“完全背包”梦寐以求的特性吗？！**
*   在完全背包求最值（比如力扣 322. 零钱兑换求最少硬币、力扣 279. 完全平方数）的场景下，题目本身就允许我们无限次使用物品！

**【深刻的哲学关联】**
还记得我们在前一轮对话中推导出的结论吗？
*   先容量，后物品 $\rightarrow$ 本质是在求**排列（Permutations）**。
*   先物品，后容量 $\rightarrow$ 本质是在求**组合（Combinations）**。

如果你用“先容量，后物品”来解《零钱兑换》（求凑成总额的**最少**硬币数），底层虽然计算了所有可能的“排列顺序”（比如先拿1再拿2，和先拿2再拿1），**但这丝毫不影响最终硬币的【总个数】和【总价值】！**
找最小值/最大值，不管你是按组合找，还是按排列找，**极值永远是那个极值！**

这也就完美解释了：**为什么你在做《279. 完全平方数》时，你本能写出的代码（外层容量 `i`，内层完全平方数 `j`），同样能够 100% 满分 AC！因为你在用求排列的方式，求了一个极值！**

> “面试官您好，这道题求的是最少硬币数。虽然我写的是先物品后容量的正统完全背包模板（本质是求组合的最值）；但实际上，就算我把内外层循环调换（变成求排列的最值），最终得出的最少硬币数也是一模一样的。
> **不过，0-1 背包绝对不能这么换。因为一旦把容量放到外层，一维数组就会失去隔离性，导致同一个物品被重复选取。**”

## 外什么0-1背包问题内层循环必须倒序遍历，而完全背包问题内层循环必须正序遍历？

### 🟩 0-1 背包的降维真相：依赖“左上方”的幽灵

**二维公式**：`dp[i][j] = max(dp[i -1][j], dp[i - 1][j - w[i]] + v[i])`

**矩阵画面**：
我们在填第 `i` 行的第 `j` 个格子时，眼睛必须盯着两处：
1. **正上方**的旧值：`dp[i-1][j]`
2. **左上方**的旧值：`dp[i-1][j - w[i]]`

**一维压缩的灾难与破局**：
既然我们把二维矩阵压扁成了一维数组（所有的行合并成了一行），那么数组里的值就处于“新旧交替”的混沌状态。
*   如果**正序（从左往右）**遍历：当我们走到 `j` 时，它左边的 `j - w[i]` **已经在这轮循环中被算过、被覆盖成最新一行的值（即 `dp[i]` 的值）了！** 此时你再去取，取到的根本不是你想要的左上方的旧值，而是**正左方**的新值！这就是同一个物品被重复放入的灾难根源。
*   所以，**必须倒序（从右往左）**遍历：当我们走到 `j` 时，由于我们是从右边过来的，左边的 `j - w[i]` **还完全没有被碰过！** 它完美地保留了上一层（`i-1`层）的历史快照。这样，左上方的幽灵就被我们成功捕捉到了！

### 🟥 完全背包的降维真相：依赖“正左方”的新生

**二维公式**：`dp[i][j] = max(dp[i - 1][j], dp[i][j - w[i]] + v[i])`

**矩阵画面**：
我们在填第 `i` 行的第 `j` 个格子时，眼睛必须盯着两处：
1. **正上方**的旧值：`dp[i-1][j]`
2. **同层正左方**的新值：`dp[i][j - w[i]]` （注意！这里的 `i` 是当前的行号！）

**一维压缩的奇迹与破局**：
完全背包的物理意义是：我拿了一个物品后，在这个容量基础上，我**还可以继续拿这个物品**！
*   如果**倒序（从右往左）**遍历：当我们走到 `j` 时，左边的 `j - w[i]` 还没被更新，它依然是上一层的旧值。这违背了公式里要求取本层新值（`dp[i]`）的数学铁律。
*   所以，**必须正序（从左往右）**遍历：当我们走到 `j` 时，左边的 `j - w[i]` 刚刚在几微秒前被我们更新成了最新一层的状态（即装入过该物品的状态）。我们拿着这个**新鲜出炉的本层状态**继续加价值，就完美实现了“无限次重复装入”的数学逻辑！
